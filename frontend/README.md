# TELEPAT Frontend Integration

The production site stays in `quantareon-site`. This folder contains only the
small client modules needed to connect that page to the new TELEPAT backend.

## Voice client

Load:

```html
<script>
  window.TELEPAT_WS_URL = "wss://YOUR-MODAL-ENDPOINT/ws/voice";
</script>
<script src="/telepat-voice.js"></script>
```

Create the client from a user action:

```js
const voice = TelepatVoice.create({ language: "ru" });

startButton.addEventListener("click", async () => {
  await voice.start();
});

stopButton.addEventListener("click", () => voice.stop());
```

Listen for state changes:

```js
window.addEventListener("telepat:transcript", e => {
  console.log("USER:", e.detail.text);
});

window.addEventListener("telepat:reply", e => {
  console.log("TELEPAT:", e.detail.text);
});

window.addEventListener("telepat:state", e => {
  // listening / thinking / speaking / stopped / disconnected
  setAvatarState(e.detail.state);
});
```

## Identity

The browser stores a random `telepat_user_id` generated by TELEPAT itself.
It is not derived from browser/device fingerprinting.

The current conversation id lives in `sessionStorage`. A new browser tab can
start a new session while still recognizing the same returning user.

## Audio

Microphone transport is PCM16 mono at 16 kHz. The client reuses the proven
QUANTAREON resampling algorithm and keeps mobile automatic gain control enabled.

The first integration receives one MP3 payload per TELEPAT answer. Later the
same WebSocket event surface will switch the final step to the GPU avatar
stream without changing the conversation/orchestration APIs.
